v0.3 Built for multi-repo platforms

Keep a whole platform in your agents' heads.

When one production platform spans many repositories and a swarm of agents works on it at once, context is the bottleneck. Context Garden shares system knowledge across repos and agents, and trims what each agent reads. Everything runs offline, with no LLM calls inside the tools.

Why it exists

One platform. Many repos. Many agents.

Production platforms are split into components that live in separate repositories. To change one safely, an agent needs to know the system around it: what each repo provides, what depends on it, which conventions hold everywhere. When you spawn several agents for a swarming task, each one pays to rediscover that, and they read the same files in parallel.

Many reposAgents don't know the system around a component. greenhouse keeps a card per repo (provides, depends on, key facts) in a shared base folder.
Many agentsA swarm re-explores the same code in parallel. mycelium gates each spawn, stops duplicates and shares findings as notes.
Many filesEach agent reads whole files and full logs. pruner and compost cut that to exact ranges and root errors.
Many sessionsThe same facts get rediscovered every day. seedbank promotes them into a small, always-loaded AGENTS.md.

Why use it

Less noise in, more signal out.

A coding agent pays for every token it reads, and it re-reads the same things every session: full build logs, whole files, the same setup docs. Context Garden removes that repeat cost.

The honest part: what it costs

  • Always-loaded descriptions. With the plugin, each skill's one-line description is listed to Claude, about 60 to 100 tokens per skill, even when the skill is off.
  • Overhead on small tasks. In the v0.2.0 benchmark the fixtures are tiny, so forcing compost or pruner used 17 to 19% more tokens. The savings above come from real-sized logs and files.
  • Hooks are opinionated. With compost on, raw build and test commands are denied and replaced with the compost command (set hook to ask, rewrite or off). With mycelium on, an agent spawn without a proper brief is sent back.
  • Local state. Stores live in .seedbank/, .compost/, .pruner/ and .mycelium/ at the git root, and each writes its own .gitignore. A greenhouse base is a plain folder beside your repos; share it like any other folder.
Six skills

One garden, six tools.

Two work across the platform and the swarm, three cut what each agent reads, and one keeps the skills themselves small. Install all of them as a plugin or copy only the ones you need. Each skill is self-contained and uses only the Python standard library.

🏡 greenhouse multi-repo

Shared memory across the repos of one platform. Each repo keeps a card with what it provides, what it depends on and its key facts, so your agent knows the neighbours without reading them.

For platforms of many repos

🍄 mycelium subagents

A delegation gate for subagents. Briefs stay bounded, duplicate investigations get stopped, and findings are shared as notes so the next agent starts from what is known.

No investigation done twice

✂️ pruner code

Picks the smallest set of file:start-end ranges for a bug, traceback or change in a large Python or C/C++ repo. No more grepping around and reading whole files.

Reads only what matters: −66%

♻️ compost logs

Runs long builds, test suites and CI jobs through a clustering summarizer. You get the root errors and counts instead of thousands of lines, and re-runs show only what changed.

Best for fix, test, fix loops: −97%

🌰 seedbank memory

Notices facts your agent keeps rediscovering, like build commands, conventions and past mistakes, and promotes them into a small, always-loaded AGENTS.md.

Every later session: −92%

🌾 weeder skills

Audits a Skill and produces a smaller copy that keeps every instruction and still routes correctly, with before and after evidence. Trims the cost every installed skill adds to each session.

Slimmer skills, same routing

How it works

      
Hooks do the work. Skills teach the agent.

      
Deterministic parts run as Claude Code hooks, so they work even when the agent forgets. Skills explain the how, and jobs worth delegating ship as agents. All state lives in small JSON stores at your git root.

    

    

      
    


    

      
OfflineNo network, no API key, no LLM calls inside the tools.

      
DeterministicSame input, same output. Easy to trust and to test.

      
Self-containedStdlib only, no imports across skills. Copy one and go.

      
Never clobbersWrites only inside its own markers. Your content stays yours.

    

  






  

    

      
You stay in control

      
Off until you say so.

      
Every skill starts off: nothing runs, not even its hooks. Turn on what you want, per repo or everywhere. Ask Claude, for example "turn compost on", or set it yourself.

    

    

      
off
Nothing runs. The skill declines if called and tells you how to turn it on. The default.

      
manual
Runs only when you ask, for example /context-garden:compost summarize the failing run. Hooks stay quiet.

      
on
Claude uses it on its own when relevant, and its hooks run. Recommended for compost, pruner and seedbank.
